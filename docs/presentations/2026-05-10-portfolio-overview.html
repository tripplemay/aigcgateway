harness-template —— 把工程纪律变成 repo

三角色不重叠

  • Planner — 拆需求、写 spec、做架构决策
  • Generator — 按规格写代码，不评估自己
  • Evaluator — 设计测试、签收（独立工具）

7 状态机

new→ planning→ building→ verifying
⇄ fixing⇄ reverifying→ done

分层记忆

  • T0 必读 — 项目状态 / 环境信息
  • T1 角色 — 当前角色行为规范
  • T2 按需 — 触发条件命中才加载

沉淀路径

  • aigcgateway = 第一个落地 — 边做边迭代
  • kolmatrix = 第二个落地 — 同日抽出 template
  • 未来项目 N = npx degit + bootstrap.sh 即用

Portfolio Briefing 第六幕 · 方法论
机制揭示

怎么做到的 —— 3 个互相强化的机制

01
中枢复用 · 一次建好，跨项目共享
aigcgateway = 多服务商 / 计费 / 对账 / MCP 一次解决 → trainbot 当天就能挂上，AIdash / kolmatrix / pt-download-bot 走 OpenAI 兼容协议即插即用。
02
工作流沉淀 · 第二个项目时建 template
第一个项目（aigcgateway）走通后立刻抽出 harness-template，kolmatrix 同日采用。 不是过早抽象（第一个项目时），也不是错过窗口（第三个时），而是"刚好需要的时刻"。
03
AI 协作工程化 · 设计流程，让 AI 走流程
Triad 三角色（Planner / Generator / Evaluator）+ 状态机 + 分层记忆 —— 不是"我和 AI 一起写代码"，是"我设计流程，AI 走流程"。 没有这套约束，AI 协作会失忆 / 重复劳动 / 无法接力。
这三个机制互相强化：中枢让应用层快，工作流让基础设施稳，AI 协作让两者都可持续。
Portfolio Briefing 第六幕 · 方法论
最终 takeaway · 可外溢到任何团队

三条可外溢经验

01
基础设施在"第二个项目时"建
第一个项目时建 = YAGNI，过度抽象拖慢交付。
第三个项目时建 = 沉没成本，三套独立代码已经长大。
第二个项目要复用的那一刻，是抽出 template 的最佳窗口。
02
方法论沉淀比"做更多项目"更稀缺
做 8 个项目 = 重复 8 次相同的脚手架 + 决策 + 踩坑。
做 1 个项目 + 1 套方法论 + 7 次复用 = 同样的产出，1/3 的成本。
harness-template 独立 repo 是这一条的物理证据。
03
AI 协作的天花板 = 工程纪律的厚度
"AI 写代码快不快"是错误的问题。
正确的问题是："我有没有给 AI 设计好规则、状态、记忆、验收"。
prompt 不是核心，状态机 + 记忆分层 + 三角色约束才是。
