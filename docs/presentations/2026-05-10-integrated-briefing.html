汇报 · 2026-05 第二幕 · 重点 1 · aigcgateway 中枢
问题全景

典型 AI 应用的现状是什么样？

Prompt 维度
字符串散落，无人治理
• prompt 写死在前端 / 后端 / 脚本里
• 没有版本号、没有 changelog
• 改一处要找十处、回滚靠 git revert
• 测一次新 prompt 要发一次版
服务商维度
10 家 SDK · 10 种风格
• 不同 schema、不同计费、不同重试策略
• 单个上游挂了，整条调用链跟着挂
• 多 key 管理、多账单对账
• 调用出问题不知道是哪家的事
Prompt 复杂度 × 服务商复杂度 = 复杂度雪球 —— 靠加人解决，越加越乱。

汇报 · 2026-05 第三幕 · 重点 2 · kolmatrix · 借机展开方法论
方法论 · 之一

三角色不重叠 — 无人评估自己的工作

Planner · 用 Claude
规划 / 仲裁
读 backlog · 写 spec · 拆 features.json
做架构决策（ADR）
出现争议时仲裁
不准改产品代码，hotfix 也走流程
Generator · 用 Claude
按规格写代码
不发明需求
不评估自己
只把 spec 翻译成可运行代码
铁律：不准写自己的测试
Evaluator · 用 Codex
设计测试 + 签收
独立工具，完整拥有测试域
输出 PASS / FAIL
critical 修复必带回归测试
不同工具切掉"自评"的物理可能
关键设计：Generator 用 Claude，Evaluator 用 Codex —— 用不同工具把"自评"从源头切掉。 比"我承诺会客观验收"强 100 倍。

方法论 · 之二

状态机 + 分层记忆 + Git 总线

7 状态硬流转 · progress.json 是唯一真理源
new→ planning→ building→ verifying⇄ fixing⇄ reverifying→ done
分层记忆 (T0/T1/T2)
上下文窗口 = 节流
T0 必读 · 项目状态 / 环境信息（≤30 行）
T1 角色 · 当前角色行为规范（≤50 行）
T2 按需 · 触发条件命中才加载
分层加载 ≠ "按感觉"，是确定性规则
Git 作为协作总线
跨设备无缝接力
progress.json · 阶段 + 角色分配
.auto-memory/ · 跨 agent 共享记忆
.agent-id · 不入 git，本机身份隔离
早上台式机 Planner，下午笔记本 Reviewer
AI agent 启动第一件事：读 status，不匹配自己角色就直接退出 —— 不靠它"自觉"，是状态机硬不让它干。

真实事故沉淀

框架不是设计出来的，是 踩出来的

v0.5.0 共享记忆分层 T0 / T1 / T2 起因：上下文塞满后第二次会话完全失忆
v0.9.0 Pre-Impl Audit 模式 起因：Generator 开工后才发现 spec 与实物代码脱节
v0.9.4 铁律 #10: commit-tag 必对应 feature 起因：Planner docs commit 误带 9 文件 WIP 入 main，需 revert
v0.9.18 auth role enum 实物核查 起因：字面 'admin' vs 真实 'tenant_admin' → 上线被踢回
v0.9.19 外部 API zod schema 实物 sample 验证 起因：单测 mock PASS 但 prod 50/41 row 触发 parse error
诚实点：从 v0.1.0 到 v0.9.20 共 30+ 个版本，每条铁律背后都是一次真实事故。 这些都被沉淀进 framework，下个项目不用再踩。

汇报 · 2026-05 第四幕 · 收尾 · 经验外溢
最终 takeaway · 可外溢到任何团队

三条可复用经验

01
不让 AI 评估自己的任何产出
Generator 用 Claude，Evaluator 用 Codex —— 用不同工具把"自评"从源头切掉。 规划 / 实现 / 验收不能由同一 agent 兼任，哪怕它"能力很强"。
02
AI 协作的核心，不是 prompt，是状态机 + 记忆分层
协作不是"我和 AI 一起写代码"，是"我设计流程，AI 走流程"。 没有状态机 → 失忆 / 重复劳动 / 无法接力；没有记忆分层 → 上下文爆炸 / 注意力稀释。
03
基础设施 + 方法论 = 真正的杠杆
一次中枢复用 + 一次方法论沉淀 = 同样的产出 1/3 的成本。 aigcgateway 让应用快，harness-template 让纪律可外溢， 两者一起，AI 协作才真正发挥杠杆。
